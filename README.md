Опыт миграции решений с Oracle на PostgreSQL

Здесь собраны примеры различий в работе приложений на Oracle PL/SQL и PostgreSQL PL/pgSQL, которые надо учитывать при миграции с Oracle на PostgreSQL.
Примеры я выполнял в базах Oracle 12c и PostgreSQL 14.3 с установленным расширением plpgsql_check.

## 01 Управление транзакциями внутри процедур
Одно из фундаментальных различий, которое может помешать переносить алгоритмы процедур "один в один", - это работа с транзакциями внутри процедур.

Oracle очень гибко позволяет это делать: применить Commit или Rallback можно в любой части процедуры или функции, транзакция остается активной даже если в процедуре возникло исключение.

## 02 Компиляция хранимых процедур
Оракл в момент создания процедуры не только сохраняет ее текст на сервере, но и проводит компиляцию в байт код. В процессе компиляции процедура проходит синтаксические и семантические проверки (типы данных и области видимости), проверки существования и валидности объектов, прав доступа. Благодаря этому большая часть ошибок в процедуре обнаруживается на этапе компиляции.
02_compilation_ora.sql

PostgreSQL в момент сохранения процедуры осуществляет только самые базовые проверки. Настоящая компиляция происходит в момент первого запуска процедуры в рамках сессии.
Это приводит к тому, что PostgreSQL без ошибок примет процедуры с самыми разными ошибками в коде, и обнаружатся они только в момент выполнения.
Компенсировать этот недостаток может расширение plpgsql_check - статический анализатор, показывающий ошибки, которые могут вылезти при выполнении кода.
