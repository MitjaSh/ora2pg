# ora2pg
Experience of solutions migration from Oracle to PostgreSQL

Опыт миграции решений с Oracle на PostgreSQL

Здесь собраны примеры различий в работе приложений на Oracle PL/SQL и PostgreSQL PL/pgSQL, которые надо учитывать при миграции с Oracle на PostgreSQL.

Примеры я выполнял в базах:
- Oracle 12c,
- PostgreSQL 14.3 с установленным расширением plpgsql_check,
- Postgres Pro (enterprise) 17.7.1 - для демонстрации пакетов и автономных транзакций;

## 01 Управление транзакциями внутри процедур
Одно из фундаментальных различий, которое может помешать переносить алгоритмы процедур "один в один", - это работа с транзакциями внутри процедур.

Oracle очень гибко позволяет это делать: применить Commit или Rallback можно в любой части процедуры или функции, транзакция остается активной даже если в процедуре возникло исключение.  
*01_transactions_ora.sql*

PostgreSQL накладывает несколько ограничений на управление транзакциями в хранимых процедурах.  
*01_transactions_pg.sql*

## 02 Компиляция хранимых процедур
Oracle в момент создания процедуры не только сохраняет ее текст на сервере, но и проводит компиляцию в байт код. В процессе компиляции процедура проходит синтаксические и семантические проверки (типы данных и области видимости), проверки существования и валидности объектов, прав доступа. Благодаря этому большая часть ошибок в процедуре обнаруживается на этапе компиляции.  
*02_compilation_ora.sql*

PostgreSQL в момент сохранения процедуры осуществляет только самые базовые проверки. Настоящая компиляция происходит в момент первого запуска процедуры в рамках сессии.  
Это приводит к тому, что PostgreSQL без ошибок примет процедуры с самыми разными ошибками в коде, и обнаружатся они только в момент выполнения.  
Компенсировать этот недостаток может расширение plpgsql_check - статический анализатор, показывающий ошибки, которые могут вылезти при выполнении кода.  
*02_compilation_pg.sql*

## 03 Работа с NULL в строках
Oracle при операциях сравнения считает пустую строку '' эквивалентной NULL. При этом конкатинация исходной строки с NULL (и с пустой строкой '') возвращает исходную строку.  
*03_nullstr_ora.sql*

PostgreSQL не считает пустую строку '' эквивалентной NULL. И при конкатинации с NULL, руководствуется принципом, что любая операция с NULL возвращает NULL.  
*03_nullstr_pg.sql*

Эта разница в поведении может привести к потере строковых значений при переходе на PostgreSQL.  
Чтобы избежать ошибок надо везде, где идет конкатинация с потенциальным значением NULL, оборачивать переменную/поле функцией coalesce. Или делать конкатинацию не при помощи оператоа ||, а при помощи функции concat (concat_ws).

## 04 Пакеты
В Oracle пакеты позволяют:
- реализовать инкапсуляцию и запретить внешний доступ к процедурам/функциям/глобальным переменным, созданным только для внутреннего использования;
- группировать процедуры и функции, управлять доступом для всего пакета, а не для отдельных его составляющих;
- использовать глобальные переменные, которые живут на всем протяжении сессии;
- выполнять инициализационный код один раз за сессию при первом обращении к пакету;  
*04_package_ora.sql*

В ванильном PostgreSQL поддержка пакетов отсутствует.
В Postgres Pro ее реализовали через отдельные схемы.
*04_package_pg.sql*
